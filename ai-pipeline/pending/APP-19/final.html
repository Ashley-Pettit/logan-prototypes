    How it works. Each position description is checked against a sample list of Chain of Responsibility duty areas, using the role's party type (for example scheduler, loader or executive) to decide which duties it should carry. Rules give a first pass straight away; AI reads the whole description, quotes the line that covers each duty and suggests wording for the gaps. You can change any result before copying the gap summary for HR or the manager.
    Prototype handover notes
    • In the LCC stack for production: HTML, CSS and JavaScript front end (move to Vue and Bootstrap) on Azure App Service, an Azure Function App for model calls, SQL for roles, duty mappings and review history, Entra ID sign-in.
    • Needs an ICT-DA exception: Claude (Anthropic) as the AI provider, through the council's enterprise agreement or Microsoft Foundry.
    • Privacy: names, email addresses and phone numbers in a position description are swapped for placeholders before anything goes to AI. Position descriptions describe roles, not people.
    • The duty areas, party types and suggested wording are samples. They must be checked against the Heavy Vehicle National Law, the regulator's guidance and the council's CoR procedure, and agreed with People and Culture before any position description changes.
    • Still needed for production: the approved position description library from the council's HR system, an agreed CoR duty register, a test plan with an AI evaluation set, Dev, Test and Prod environments, and ICT-DA, CAB and business owner approvals.
