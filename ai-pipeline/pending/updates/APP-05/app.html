Depot chargers (sample)

    Telematics for the last 22 working days, sample data. Change an assumption and every number updates.

    How it works. The page reads 22 working days of telematics for each vehicle, with the fleet register and depot charger details. It flags vehicles used on fewer days than your threshold, checks each petrol or diesel vehicle against a similar electric model for range, duty and overnight charging, finds trips that leave the same depot for the same place at about the same time, and costs each recurring route. A brief for managers sums it up and can be copied into an email. AI then explains the recommendations in plain English and answers questions, quoting the vehicles it relied on. Without AI, the page shows the same rules-based recommendations with template wording.
    Prototype handover notes
    • In the LCC stack for production: HTML, CSS and JavaScript front end (move to Vue and Bootstrap), Azure Function App for model calls and the nightly calculations, Data Factory or Boomi to bring in telematics, fleet register and fuel card data, and SQL Server (through the Data Warehouse where possible) for history.
    • Needs an ICT-DA exception: Claude (Anthropic) as the AI provider, through the council's enterprise agreement or Microsoft Foundry.
    • Privacy: telematics can show where an individual driver went and when. Production must aggregate by vehicle and depot, never send driver names, home addresses or trip start and end points near homes to the model, and agree use with Human Resources and the unions before launch.
    • The numbers are estimates. Fuel, electricity and emission factors, and the sample electric models, must be replaced with City Fleet's real figures and approved replacement models before any decision.
    • Still needed for production: real fleet, telematics and charger data, a test plan with an AI evaluation set (questions with known answers), Dev, Test and Prod environments, and ICT-DA, CAB, PGG and Business System Owner approvals.
